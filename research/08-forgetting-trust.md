# 08 — Forgetting, provenance, and trust

Planning recommendation for Kivi's 500-transcript memory; sources verified 2026-09-05. The policies below are proposed design decisions, not claims that a library supplies them.

**Define separate operations.** “Forget this memory” removes the selected fact and its derived summaries, embeddings, graph assertions, and response caches from assistant use. Retain the transcript only if the interface explicitly says so; exclude supporting spans from retrieval and future extraction. “Delete source” removes Kivi's transcript copy, chunks, indexes, and derivatives; invalidate mixed-source summaries and recompute from surviving evidence. A separately supported fact may survive source deletion, but must not survive an explicit request to forget that fact. Neither operation deletes an external original automatically. Mem0 documents memory-ID and scoped-filter deletion plus search verification; that is a useful primitive, not evidence of end-to-end source erasure. [Mem0 deletion documentation](https://docs.mem0.ai/core-concepts/memory-operations/delete)

**Prevent resurrection.** Commit a durable, user/project-scoped tombstone before background cleanup. Record opaque source/version/span IDs and excluded attribute categories, never the deleted value. Check exclusions during ingestion, extraction, consolidation, retrieval, and before committing delayed jobs. Bump a memory generation so old jobs and cache entries cannot reappear. Reimports and backup restores must replay exclusions before becoming searchable. Opaque IDs alone cannot recognize unrelated paraphrases: a broader user-selected category exclusion provides stronger prevention without retaining the secret; explain that tradeoff. Re-enabling collection requires an explicit user action. Report immediate retrieval blocking separately from completed physical cleanup, including backup expiry and any processor-held copies.

**Keep evidence while it exists.** Each fact needs source ID, version, speaker, timestamp/span, extraction version, and confidence; each summary needs its dependencies. Distinguish direct statements from inference and assistant-generated text. After deletion, retain only an audit event with opaque IDs, actor, time, scope, status, and non-content counts. Display “source deleted” rather than keeping quotations, old fact values, sensitive filenames, or free-text deletion reasons. OWASP explicitly advises excluding secrets and sensitive personal data from logs; an audit log must not become a second memory store. [OWASP logging guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

**Enforce ownership outside the model.** Derive user/project scope from authenticated server context for every source, memory, cache, export, and future tool call. Deny missing scope; do not accept model-supplied ownership as authorization. Keep personal and shared-project memory separate unless explicitly shared. Database row policies can reinforce isolation, but PostgreSQL owners, superusers, and BYPASSRLS roles can bypass them; use an appropriately restricted application role. [PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

**Imported text remains data.** Transcript instructions and retrieved memories cannot change policy, permissions, recipients, or tools. Extraction may propose attributed facts; it cannot grant authority or persist executable instructions. Restrict future tools independently and require authorization for external effects. A 2026 preprint demonstrates planted memory payloads influencing current and later sessions; it does not establish a complete defense. Test malicious transcripts, cross-project retrieval, delayed writes after forgetting, and restoration after deletion. [Bad Memory](https://arxiv.org/abs/2607.14611)
