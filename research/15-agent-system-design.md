# 15. Independent agent-system design challenge

Reviewed 5 September 2026. Planning only; no implementation or measured results.

Reading scope: inspected the tools, planning, reflection, failure and evaluation discussions in Chip Huyen's author-published adaptation of the **Agents section** of *AI Engineering*, plus Anthropic's *Building effective agents*, including its appendices. This is **not a complete reading of either a book or a book collection**. Huyen explicitly defers memory-system mechanics to a future post; her agent discussion cannot validate this particular memory schema. [Author-published section](https://huyenchip.com/2025/01/07/agents.html)

The architecture proposal and product questions are coherent, but the strongest counterargument is that the implementation order commits to extraction before establishing whether extraction improves the product. Five hundred records might fit the selected model's usable context; record count alone does not establish this. Extraction introduces another opportunity to lose attribution, negation and corrections, and incurs maintenance and ingestion costs.

**Long context versus memory.** Promote full permitted history and source-only hybrid retrieval from diagnostic baselines to genuine deployment candidates. Measure corpus tokens, task quality, citation support, p95 latency and total cost, including preprocessing amortized over realistic query volumes. Run both equal-budget comparisons and each system's best achievable quality/cost configuration; forcing identical evidence budgets would handicap the long-context candidate. A published comparison found sufficiently resourced long context stronger on average in its evaluated settings, with retrieval offering lower cost; this does not establish the outcome for DeepSeek or Hindi/Hinglish. If source-only or full-history answering meets the agreed targets and typed memories offer no meaningful improvement, retain the source/lifecycle ledger and postpone general extraction. [Li et al., EMNLP 2024, abstract inspected](https://aclanthology.org/2024.emnlp-industry.66/)

**Autonomy versus workflow.** Keep ingestion, validation and ordinary recall as explicit workflows. Allow bounded search reformulation when evidence is insufficient, with typed read tools, a call/token/time budget and observable termination. Anthropic distinguishes predefined workflows from model-directed agents and recommends increased complexity only for demonstrated benefit; its article now warns that tooling has changed since December 2024. Overturn the workflow recommendation when representative tasks require unpredictable investigation and an adaptive loop improves held-out completion enough to justify its latency and failures. Persistent memory writes and external actions still need separate authority. [Anthropic guidance](https://www.anthropic.com/engineering/building-effective-agents)

**Graph versus relational.** A relational representation of supported relationships already constitutes a logical graph. SQLite documents recursive graph queries. A graph engine will not repair a wrong entity merge or unsupported edge. Challenge SQLite when realistic traversal depth, concurrent workload, temporal queries or developer effort become limiting; compare implementations using identical extracted evidence. Adopt a graph engine only for a measured operational or query advantage. [SQLite recursive graph queries](https://www.sqlite.org/lang_with.html)

**Unwanted personalization.** My product recommendation is to separate permission to store, permission to retrieve, and appropriateness of revealing a remembered fact. Ordinary dictation should preserve intended content. Test neutral answers, silent adaptation and explicit callbacks against the same requests; measure usefulness and discomfort separately. “Visited Paris” neither implies liking France nor makes a personal callback useful. Prefer no callback when it adds no task value; let explicit present instructions override historical preferences.

Material omissions to resolve before development:

- Define the exact invocation boundary between faithful dictation and memory-assisted Hey Kivi behavior, including generated drafts destined for other people.
- Specify how conflicting raw ASR and formatted text affect admission; retaining both does not determine which claim is supportable.
- Define holdout construction, acceptance margins, latency/cost targets and failure severity before choosing the winning variant.
- Specify consistent reads during reindexing/correction and what forgetting covers in logs, backups and in-flight provider requests.

Conditional verdict: retain SQLite, provenance and bounded workflows; move comparative baselines ahead of comprehensive extraction. These are testable engineering judgments, not conclusions established by reading books.
