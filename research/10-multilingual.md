# 10. Multilingual memory

Research checked 5 September 2026. Scope: approximately 500 English, Hindi Devanagari and Romanized Hinglish logs, each with raw ASR and formatted text; local Windows CLI, no guaranteed GPU. These are planning recommendations, not measured Kivi results.

**Start with multilingual-e5-small plus lexical retrieval; compare BGE-M3 before upgrading.** E5-small produces 384-dimensional vectors and accepts at most 512 tokens. Its retrieval inputs require the literal English prefixes `query: ` and `passage: ` even for Hindi. Use normalized embeddings, the checkpoint's tokenizer and tokenizer-aware chunks; leave room for prefixes and special tokens. Cache document embeddings and load the model once per CLI session. The smaller checkpoint is a practical CPU baseline candidate, but Windows latency and memory must be measured. [E5-small model card](https://huggingface.co/intfloat/multilingual-e5-small)

BGE-M3 provides 1024-dimensional dense embeddings, an 8192-token context, and optional sparse and multi-vector retrieval. It does not require query instructions. Evaluate its dense mode first against E5 using identical chunks and lexical fusion, then test its additional retrieval modes separately. Its larger context does not justify embedding an entire multi-topic log as one unit. Neither model's multilingual coverage proves superiority on this corpus, Romanized spellings or ASR errors. [BGE-M3 model card](https://huggingface.co/BAAI/bge-m3)

**Preserve evidence while adding searchable representations.** Keep immutable raw ASR and formatted text as separate fields under one source-log ID, with provenance and offsets. Index both when their wording differs; consolidate retrieval hits by source ID so duplicate representations do not crowd out other logs. Formatting is a derived representation and cannot silently override ambiguous raw evidence.

For lexical search, maintain a separate NFC-normalized view and tokenize Unicode letters, combining marks and numbers together. Verify Hindi matras, nukta and virama remain attached; avoid ASCII-only tokens and blanket combining-mark removal. Keep the original text for citations and map transformed spans back to it. Dense tokenization remains the model's own tokenizer.

Store contextual aliases such as `Rahul`/`राहुल` and observed Roman spelling variants as retrieval aids with provenance. Similar spelling, transliteration or embedding proximity must not merge people, places or events automatically. Optional transliteration or translation creates another searchable view or query expansion; it never becomes the sole source of truth. Preserve negation, numbers, dates and uncertainty across all views.

**Evaluate the actual language combinations.** Hindi-BEIR covers 15 datasets and seven tasks, offering relevant Hindi retrieval evidence but no guarantee for personal Hinglish memory. [Hindi-BEIR paper](https://aclanthology.org/2025.naacl-long.220/) FIRE-2016 MSIR section 3 specifically evaluates Romanized Hindi-English query-to-tweet retrieval; its test set has only 12 queries and excludes mixed Roman/Devanagari text, limiting transfer to Kivi. [MSIR primary paper](https://personales.upv.es/prosso/resources/BanerjeeEtAl_FIRE16.pdf)

Create a held-out, manually judged query set covering English↔Hindi, Devanagari↔Roman, code-switches, spelling variants, ASR noise, names, negation and time references. Compare lexical-only, E5-only, lexical+E5 and lexical+BGE-M3; measure Recall@5/10, ranking quality, source-citation correctness, peak RAM, indexing time and cold/warm query latency. Report each language slice and duplicate-source handling.

NVIDIA's `llama-3.2-nv-embedqa-1b-v2` is an optional hosted comparator: its documentation includes Hindi among 26 evaluated languages and supports 8192 tokens. Its reported multilingual benchmark uses a reduced internal corpus, so scores are not directly comparable to local results. A DeepSeek generation credential does not establish embedding endpoint availability; verify access later and keep embeddings independently configurable. [NVIDIA model documentation](https://docs.api.nvidia.com/nim/reference/nvidia-llama-3_2-nv-embedqa-1b-v2)
