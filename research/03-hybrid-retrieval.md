# Hybrid retrieval for Kivi's 500-record memory

**Recommendation:** start with local BM25 plus exhaustive dense similarity, fuse their rankings, then optionally rerank a bounded candidate set. Treat the following pipeline and tuning values as design proposals requiring evaluation on Kivi's transcripts, not measured results.

1. **Prepare source-linked representations offline.** Retain immutable raw ASR and formatted text under one record ID. Store recording timestamp, extracted event date with uncertainty, source spans, and entity mentions. Index short records whole; split long records at topic boundaries while retaining neighboring context. Prepend a short, source-supported description identifying the meeting, participants, and topic to each chunk's retrieval representation. Anthropic's contextual retrieval applies explanatory prefixes before both embedding and BM25 indexing; generated prefixes must remain distinguishable from original evidence. [Anthropic method](https://www.anthropic.com/engineering/contextual-retrieval).

2. **Keep lexical and multilingual dense routes.** BM25 protects exact names, product terms, numbers, and uncommon phrases; dense retrieval supplies paraphrase and cross-language candidates. Preserve Devanagari and Roman-script originals. Add observed aliases and conservative transliteration variants in separate fields, leaving original query terms intact. BGE-M3 is a candidate multilingual embedding model supporting dense, sparse, and multi-vector retrieval; that capability does not establish quality on Hindi-English code-switching or noisy Romanized Hindi. Evaluate those cases explicitly before selecting a model. [BGE-M3 paper](https://arxiv.org/abs/2402.03216).

3. **Search all vectors locally.** For 500 records and their actual chunk count, precompute normalized vectors and calculate query-to-corpus dot products exhaustively. This gives exact similarity rankings, without ANN candidate loss. Sentence Transformers documents this direct approach and explains ANN's recall/speed trade-off. A vector database can supply persistence, filters, concurrent updates, or deployment conveniences, but record count alone does not justify one here. Database choice and exact-versus-approximate search are separate decisions. Measure cold startup, query encoding, search, and reranking independently. [Exact semantic search](https://www.sbert.net/examples/sentence_transformer/applications/semantic-search/README.html).

4. **Fuse, deduplicate, and optionally rerank.** Start experiments with each retriever's top 30–50 chunks. RRF sums `1 / (k + rank)` across lists, avoiding direct addition of incomparable BM25 and cosine scores; `k=60` is a documented default, not a Kivi optimum. Deduplicate by source span and cap repeated chunks from one record. RRF scores are rankings, not answer-confidence probabilities. [RRF definition](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion). Batch a multilingual cross-encoder over perhaps 20–40 fused candidates only when its measured quality gain warrants latency. Cross-encoders jointly score query-document pairs, making bounded reranking preferable to scoring the entire corpus on every question. [Retrieve and rerank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html).

5. **Route history questions beyond one top-k list.** For “everything about Riya,” enumerate matching entity-linked records and use retrieval to discover omitted mentions. For “how did the plan change?”, collect evidence across dates, retaining conflicting versions. Apply explicit date constraints to the appropriate recording/event field; uncertain dates require broader retrieval. For multi-hop questions, retrieve the first entity/event, then run bounded follow-up searches using evidence-derived names or terms. Return source IDs/spans for every hop. Broad aggregation requires coverage across the relevant set, not merely the most similar snippets.

6. **Escalate to raw evidence when coverage is weak.** Search raw ASR alongside formatted text when names, negation, dates, or quotations are missing or disputed; open whole source records and neighboring chunks. Raw ASR can itself be wrong. Do not silently resolve disagreements through generated summaries.

**Failure modes to test:** ASR-corrupted names; transliteration collisions and same-name people; generated context inventing relationships; dense similarity confusing opposite decisions; duplicate raw/formatted hits inflating ranks; rerankers dropping necessary bridge evidence; and top-k selection omitting early history. Evaluate answer-support recall and date/entity coverage alongside end-to-end latency, using English, Hindi, and Hinglish questions.
