# 12. OSS choices: reuse narrowly, retain evidence ownership

Checked 5 September 2026. Scope: roughly 500 noisy records, one user, a hidden evaluation corpus, two days for a CLI and a later UI. This is a planning recommendation from current official repositories, licenses and selected code paths; no package was installed or benchmark reproduced. Five core candidates are compared below; Letta and A-MEM remain outside this bounded shortlist.

**Recommendation:** retain a small, transparent SQL system of record, use Mem0 as the first external baseline, and consider LangMem only as an extraction library. Graphiti becomes attractive if temporal relationship queries demonstrably dominate. This is an engineering judgment about delivery and inspectability, not evidence that custom memory retrieves better.

| Candidate | Verified present boundary | Proposed role and consequence |
|---|---|---|
| **Mem0 — Apache-2.0** | Library, self-hosted server and managed platform are distinct. Its April-2026 README describes ADD-only extraction and explicitly attributes headline benchmark scores to proprietary managed optimizations. Current `mem0/memory/main.py` also retains explicit update/delete/history operations and timestamp inputs. | **First baseline; possible library replacement.** Fast route to extraction and hybrid search. Wrap source IDs and correction policy explicitly; a memory update history alone does not establish whether a dated statement was true or merely recorded. Never present managed scores as OSS results. [Repository](https://github.com/mem0ai/mem0) |
| **Graphiti — Apache-2.0** | Current `EntityEdge` has episode IDs, validity bounds, invalidation time and reference time. Hybrid search combines semantic, keyword and graph signals. Requires a graph backend; Kuzu is deprecated. Zep adds proprietary infrastructure, governance and tools. | **Temporal baseline and schema inspiration.** Closest conceptual match for provenance and changing relationships. Integration, model extraction reliability and backend setup consume the two-day budget; Graphiti does not supply Zep's complete product. [Repository](https://github.com/getzep/graphiti) |
| **LangMem — MIT** | Storage-independent primitives plus LangGraph store tools. `create_memory_manager` accepts custom schemas, instructions and insert/update/delete controls. Example in-memory storage loses data on restart. | **Optional extraction library.** Useful if its structured extraction saves work with the selected model. Own the SQL persistence, evidence links and revision transactions; adopting the library does not require adopting managed LangGraph hosting. [Repository](https://github.com/langchain-ai/langmem) |
| **Cognee — Apache-2.0 core** | Local ingestion, graph/vector retrieval, CLI/UI and managed cloud exist. Embedded defaults are SQLite, LanceDB and Kuzu. The README labels its Postgres graph backend a demo; production availability is separately licensed. | **Alternative end-to-end baseline.** Broader ingestion and automatic improvement are useful later, but add behavior to inspect. Avoid assuming the advertised single-Postgres production stack is included in OSS. [Repository](https://github.com/topoteretes/cognee) |
| **Supermemory — MIT repository** | Current upstream advertises a local full-engine binary and API. Local deployment uses the supplied model, single-machine execution and logs; Enterprise adds proprietary models, connectors and organizational controls. | **Local API baseline.** A credible buy option for this single-user scale. Verify source export, correction semantics and actual local quality before making it authoritative. [Repository](https://github.com/supermemoryai/supermemory), [deployment comparison](https://supermemory.ai/docs/self-hosting/local-vs-enterprise) |

SQL is justified for immutable source records, evidence spans, separately recorded event/ingestion time, reversible supersession, and readable decision logs. Build those small product-specific rules; reuse database, embedding and retrieval components. Keep retrieval behind one interface so the later UI consumes the same answers and citations.

Timebox the first baseline integration to 90 minutes. Compare against raw-record lexical/vector retrieval on identical held-out development questions covering corrections, attribution, temporal ambiguity and unsupported answers; record citation accuracy, answer quality, latency and model cost. Adopt a library if it meets these requirements with less code. Otherwise keep the simpler core. Pin versions and prompts: papers, evolving source and hosted services are different experimental systems.
