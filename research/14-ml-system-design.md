# 14. ML systems design: evidence before complexity

Reviewed 5 September 2026 against `ARCHITECTURE_PROPOSAL.md` and `PRODUCT_QUESTIONS.md`. Scope: the author-hosted short booklet's project setup, data pipeline, modeling, and serving sections; selected public companion material for *Designing Machine Learning Systems* and *AI Engineering*; and the author's leakage exercises. This is not a claim to have read either commercial book in full. Recommendations below are applications to this project, not reported experimental results.

**Keep the basic architecture, narrow the delivery target.** Huyen emphasizes explicit user outcomes, error costs, constraints, simple baselines, and component ablations. The proposal follows this well, but its development order still risks spending both days implementing an ontology before demonstrating useful recall. Make source import, provenance, lexical retrieval, and cited answers the first complete CLI path. Compare dense/hybrid retrieval next; treat typed extraction as a measured addition. Choose one recall and one correction workflow as acceptance scenarios. Define acceptable unsupported-answer rate, answered coverage, and latency before comparing models. The booklet supports this process, not a specific SQLite or DeepSeek recommendation. [Short booklet: system design](https://huyenchip.com/machine-learning-systems-design/design-a-machine-learning-system.html)

**Make data quality inspectable.** Five hundred records are not five hundred independent examples. Paired ASR/formatted text, repeated messages, and related dictations share evidence. Add a corpus manifest with record lengths, language/script, missing metadata, duplicates, and raw/formatted disagreements. Preserve disagreement as uncertainty; a fluent formatted sentence may introduce a factual error. Review evidence spans and attribution against both variants. Synthetic questions and answers produced by the same model need independent human adjudication, especially for negation, quoted instructions, and ambiguous names.

**Turn multilingual coverage into measurable slices.** The proposal names Hindi/Hinglish but lacks a sampling plan. Report English, Devanagari Hindi, Romanized Hindi, code switching, and cross-language query/source cases separately, including ASR-corrupted names. Track slice counts and failures rather than relying on an aggregate score. A change in normalization or formatter version can resemble distribution drift; preserve those versions and compare raw-input statistics before blaming the embedding model. Huyen's monitoring notes explicitly connect pipeline errors, representation changes, and deployment mismatch. [Designing ML Systems companion notes](https://huyenchip.com/2022/02/07/data-distribution-shifts-and-monitoring.html)

**Specify leakage controls.** A feasible initial suite is 60 hand-reviewed questions: 30 development and 30 frozen evaluation, grouped by scenario/template family. Keep paraphrases of one scenario together; tune prompts, thresholds, and retrieval depth only on development cases. All permitted historical evidence can remain searchable; held-out questions and gold answers cannot enter memory. Temporal replay must restrict ingestion to records available at each query cutoff, preventing future corrections from answering earlier questions. These are proposed controls; the author's exercises illustrate duplication and temporal split leakage. [Sampling and leakage exercises](https://huyenchip.com/ml-interviews-book/contents/7.2-sampling-and-creating-training-data.html)

**Calibrate decisions and measure the whole path.** Log answer/partial/clarify/abstain outcomes against human labels; compare error rate with answered coverage on development cases, then freeze the rule. Retrieval rank and model confidence are not calibrated truth probabilities. Thirty evaluation questions provide directional evidence, not reliable calibration across every slice. Separate extraction, retrieval, generation, and evaluator failures. Record tokens, retries, timeouts, total latency, and first-token latency if streaming; budget evaluation calls too. Huyen distinguishes system metrics, model metrics, and pipeline-stage metrics. Keep NVIDIA DeepSeek as the user's configurable endpoint preference; credentials, quotas, actual costs, and performance remain untested until development. [AI Engineering companion architecture](https://huyenchip.com/2024/07/25/genai-platform.html)
